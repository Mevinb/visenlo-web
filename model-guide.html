THE PRACTICAL GUIDE / YOUR FIRST SWAP

From first launch
to your first image.

Visenlo pairs a reference identity with a target scene, processes the swap on your computer, and saves the result locally. Here is the complete path through setup and your first swap.

↳

Start in the right folder. Extract Visenlo.zip, then open the inner Visenlo/ folder containing app.py and run.sh or run.bat. Start ./run.sh on Linux/macOS, or double-click run.bat on Windows. Keep its terminal open while using the local studio.

01 / FIRST-RUN MODEL SETUP

Install from inside the studio.

The launcher prepares the Python environment and opens your local page. If it does not open automatically, use the address printed in the launcher terminal. The port can change, so use that address rather than a bookmarked port.

  1. Open Model setup.The app checks its local files and shows what is ready or missing. It does not download model weights during a swap.
  2. Review the model licenses.Read the terms linked in the panel, then check “I have reviewed the model licenses and agree to their permitted use.” Model weights have separate terms, including research and non-commercial restrictions.
  3. Choose Install required models.This installs the missing buffalo_l analysis pack and InSwapper 128 weights for the default workflow. Existing local assets are preserved. Keep the page open and follow the Model setup report.
  4. Wait for required models ready.Readiness updates after installation and the swap button becomes available. Optional parsing, restoration, and occlusion models have a separate checkbox; you can leave it off for a first swap.

02 / REFERENCE + TARGET → RESULT

Give each image its job.

  1. Choose your scene: the target.Add the photo you want to edit. This supplies the scene, pose, and surrounding image. You can add several targets to process a batch with the same references.
  2. Add a reference: the identity.Use a clear, well-lit face photo. Additional references are optional; use photos of the same person. The app supports up to four reference images.
  3. Start with the default model.Keep InSwapper 128 for your first test. Manual quality runs the selected resolution once; Best likeness compares candidates and takes longer. With several faces, choose the target index in Fine-tune: faces are numbered from 0, left to right.
  4. Run identity swap and review.Completed results appear in the gallery with a report for each target. Download the PNG from the gallery or find the automatically saved image in the project’s outputs/ folder. A failed target is reported while the rest of the batch continues.

The likeness score compares identity embeddings. Use it to compare results; assess the actual image for blending, expression, and detail. Only edit images you own or have permission to use.

03 / WHAT THE MODELS DO

Required first. Optional after.

ModelRole in the workflowNeeded for a first swap?
buffalo_lFace detection, landmarks, attributes, and identity embeddings. The complete analysis pack has five ONNX files.Yes, for the default workflow.
InSwapper 128The default face-swap model. Supports larger aligned crops through Pixel Boost.Yes, when selected.
BiSeNetFace parsing for more specific feature masks and corrections.Optional.
XSegOcclusion masks to help preserve objects in front of the face.Optional.
CodeFormerGuarded face restoration. The pipeline checks reference similarity before accepting the restored face.Optional.

Choosing a different swap model can require additional weights or a separate runtime. The core installer prepares the default InSwapper workflow, not every model in the menu.

04 / WHEN SOMETHING NEEDS ATTENTION

A clearer next step.

The page does not open.

Keep the launcher terminal open and check its last message. Open the exact local address it prints on the same computer. If setup stopped with a dependency error, fix that error before trying the browser again.

Installation stops or models stay missing.

Read the Model setup report. Check your connection and available disk space, then retry; existing files are preserved. Confirm InSwapper 128 is selected for the core installer. Other models can need different files or approved upstream access.

The first swap is slow on CPU.

Use Manual quality and native InSwapper 128 for a first test. Best likeness compares multiple candidates; high Pixel Boost settings and restoration add work. The first run also loads models into memory.

No face is found, or the wrong face changes.

Use a sharper image with a larger, unobstructed face. Check the target and reference face indexes in Fine-tune: numbering starts at 0, left to right. For a small face, review Minimum face size rather than increasing Pixel Boost.

Python dependencies fail to install.

Use Python 3.11 or 3.12. InsightFace may need a C++ compiler: Visual Studio Build Tools on Windows, development headers and build-essential on Ubuntu, or Xcode command line tools on macOS. Keep the terminal error for diagnosis.

The result needs a better finish.

Try a clearer reference of the same identity first. Then compare mouth handling, color matching, and a modest boost. Optional parsing, occlusion, and restoration models address different parts of the finish; a larger resolution alone does not guarantee a better result.

05 / DETAIL AND PROCESSING COST

Pixel Boost changes the face crop.

The resolution is the aligned face crop processed by a supported model, not the dimensions of the whole output image. InSwapper 128 uses these tile counts:

Aligned cropTile passesWhen to try it
128px1Native model size; a useful first test.
256px4A modest step up in detail.
512px16More processing for a larger aligned crop.
1024 / 2048px64 / 256Expensive on CPU. Reserve for intentional comparisons.

An explicit boost choice takes precedence over automatic candidate comparison. Unsupported boosts are not silently replaced with ordinary image resizing.

06 / ADVANCED SETUP

Prefer the terminal?

The in-app installer is the straightforward first-run route. These commands remain available for local checks and explicit downloads from the extracted Visenlo folder.

Show terminal model commands

1 Check local files without network access:

LOCAL CHECK
py scripts/download_models.py --check

2 After reviewing upstream licenses, explicitly download missing core models:

EXPLICIT DOWNLOAD
py scripts/download_models.py --download

Add --all to the download command to include optional finishing models. Then re-check models in the app.

Alternative model families include ReSwapper, GHOST, HyperSwap, SimSwap, and UniFace. Some require identity conversion weights. MobileFaceSwap and FaceDancer require separate runtimes; FaceDancer remains experimental with real generator inference unverified.

Open docs/SWAP_MODELS.md in the downloaded project for the inventory, upstream sources, and model-specific setup. Being listed in the menu does not mean a model is installed.
